Centralized Quality Dashboard for Microservices

Aggregate code coverage (JaCoCo) and code quality (SpotBugs) across 40+ microservices into a single Jenkins view.

Table of Contents
  • Prerequisites
  • Approach 1: Jenkins Folder + Dashboard View (Quick Win)
  • Approach 2: Aggregator Pipeline + Custom HTML Dashboard
  • Comparison

Prerequisites

Before starting, ensure you already have:

  • Each microservice has its own Jenkins pipeline job.
  • Each pipeline runs mvn clean verify and publishes:
    • JaCoCo via jacoco(execPattern: 'target/jacoco.exec')
    • SpotBugs via recordIssues(tools: [spotBugs(pattern: 'target/spotbugsXml.xml')])
  • Plugins installed: JaCoCo, Warnings Next Generation.

Approach 1: Jenkins Folder + Dashboard View

Effort: ~30 minutes  |  Result: Native Jenkins page with job list, SpotBugs aggregation, build health

Step 1: Install the Dashboard View Plugin

  1. Go to Manage Jenkins → Plugins → Available.
  2. Search for Dashboard View.
  3. Install it. Restart Jenkins if prompted.
  4. Confirm it appears in Manage Jenkins → Plugins → Installed.

Step 2: Create a Folder for All Microservice Jobs

  1. From the Jenkins home dashboard, click New Item.
  2. Name it microservices-quality (or any name you prefer).
  3. Select Folder.
  4. Click OK, then Save.

Note: If you already have pipeline jobs for your microservices, move them into this folder: open each job → Configure → use "Move" (or recreate the jobs inside the folder).

Step 3: Ensure Each Microservice Job Is Inside the Folder

Open the microservices-quality folder. You should see all your microservice pipeline jobs listed:

microservices-quality/
  ├── order-service
  ├── inventory-service
  ├── cart-service
  ├── payment-service
  ├── ... (40+ jobs)
  └── notification-service

Each of these jobs must already publish JaCoCo and SpotBugs (via jacoco(...) and recordIssues(...)).

Step 4: Create the Dashboard View

  1. Open the microservices-quality folder in Jenkins.
  2. Click the "+" tab (or New View) at the top of the job list.
  3. Enter a name: Quality Dashboard.
  4. Select Dashboard as the view type.
  5. Click OK.

Step 5: Configure the Dashboard View

  1. In the view configuration page:

5a. Job Filters

  • Under Job Filters, select "Use a regular expression to include jobs into the view".
  • Set the regex to .* (matches all jobs in the folder).
  • Or manually check the jobs you want to include.

5b. Add Dashboard Portlets

Add portlets to the Top, Left, and Right areas:

AreaPortlet to AddWhat It Shows
TopJobs GridAll jobs in a grid with build status (green/yellow/red ball) and last build info.
LeftTest Statistics GridTest pass/fail counts per job (from JUnit/Surefire).
LeftBuild StatisticsOverall build success/failure rates.
RightTest Trend ChartGraph of test results over time across all jobs.

Click Save after adding portlets.

Step 6: Use Warnings NG Folder-Level Aggregation

Warnings NG automatically aggregates SpotBugs issues at the folder level. No extra configuration needed.

  1. Open the microservices-quality folder.
  2. In the left sidebar, click Issues (or Warnings).
  3. You will see:
    • Total issues across all microservices.
    • Breakdown by severity (High / Medium / Low).
    • Trend chart across builds.
    • Per-job breakdown — click any job to drill down into its issues.

Tip: This is the most powerful part of Approach 1. Warnings NG gives you aggregated SpotBugs issue counts + severity breakdown + trend graph across all services, with zero extra setup.

Step 7: View JaCoCo Coverage per Job

JaCoCo does not have folder-level aggregation like Warnings NG. However:

  • In the Jobs Grid portlet, each job shows its build status.
  • Click any job → Coverage to see that service's coverage.
  • Each job's build page shows the JaCoCo coverage trend chart.

Limitation: There is no native "coverage across all jobs" summary in the Dashboard View. For that, use Approach 2 below.

Approach 2: Aggregator Pipeline + Custom HTML Dashboard

Effort: ~2–3 hours  |  Result: Single HTML page with coverage % + SpotBugs by severity for every service

Overview

Create a separate Jenkins pipeline job that:

  1. Queries the Jenkins REST API to pull coverage and SpotBugs data from every microservice job.
  2. Generates a single HTML page with a table of all services, coverage %, and SpotBugs counts.
  3. Publishes it via the HTML Publisher plugin.

Step 1: Install Required Plugins

  1. Manage Jenkins → Plugins → Available.
  2. Search and install:
    • HTTP Request — to call Jenkins REST API from the pipeline.
    • HTML Publisher — to publish the generated dashboard HTML.
    • Pipeline Utility Steps — for readJSON in the pipeline.
  3. Restart Jenkins if prompted.

Step 2: Ensure Each Microservice Job Is in a Folder

All microservice jobs should be in a folder (e.g. microservices-quality). The aggregator script will query all jobs inside this folder.

Step 3: Create the Aggregator Pipeline Job

  1. From the Jenkins dashboard (or inside the same folder), click New Item.
  2. Name it quality-dashboard-generator.
  3. Select Pipeline.
  4. Click OK.

Step 4: Configure the Aggregator Job

4a. Build Trigger

  • Under Build Triggers, enable Build periodically.
  • Set the schedule, e.g. H/30 * * * * (every 30 minutes) or H * * * * (every hour).
  • Alternatively, trigger it after upstream builds using Build after other projects are built.

4b. Pipeline Script

Under Pipeline → Definition: Pipeline script. Paste the following Groovy script:

import groovy.json.JsonSlurper

pipeline {
  agent any
  options {
    buildDiscarder(logRotator(numToKeepStr: '30'))
    timestamps()
  }
  triggers {
    cron('H/30 * * * *')
  }
  stages {
    stage('Collect Metrics') {
      steps {
        script {
          def jenkinsUrl = env.JENKINS_URL ?: 'http://localhost:8080/'
          def folderPath = 'microservices-quality'
          def slurper = new JsonSlurper()

          // 1. Get list of jobs in the folder
          def folderApiUrl = "${jenkinsUrl}job/${folderPath}/api/json?tree=jobs[name,color,lastSuccessfulBuild[number]]"
          def folderResp = httpRequest(
            url: folderApiUrl,
            acceptType: 'APPLICATION_JSON',
            validResponseCodes: '200',
            authentication: 'jenkins-api-creds'  // credential ID (see Step 5)
          )
          def folderData = slurper.parseText(folderResp.content)
          def jobs = folderData.jobs

          // 2. Collect metrics for each job
          def rows = []
          for (job in jobs) {
            def name = job.name
            def color = job.color ?: 'disabled'
            def buildNum = job.lastSuccessfulBuild?.number

            def coverage = 'N/A'
            def bugsHigh = 'N/A'
            def bugsMedium = 'N/A'
            def bugsLow = 'N/A'
            def bugsTotal = 'N/A'

            if (buildNum != null) {
              // JaCoCo coverage
              try {
                def covUrl = "${jenkinsUrl}job/${folderPath}/job/${name}/${buildNum}/jacoco/api/json"
                def covResp = httpRequest(
                  url: covUrl,
                  acceptType: 'APPLICATION_JSON',
                  validResponseCodes: '200:404',
                  authentication: 'jenkins-api-creds'
                )
                if (covResp.status == 200) {
                  def covData = slurper.parseText(covResp.content)
                  def lc = covData.lineCoverage
                  if (lc != null) {
                    coverage = "${lc.percentage}%"
                  }
                }
              } catch (e) {
                echo "Coverage fetch failed for ${name}: ${e.message}"
              }

              // Warnings NG (SpotBugs)
              try {
                def issUrl = "${jenkinsUrl}job/${folderPath}/job/${name}/${buildNum}/warnings-ng/api/json"
                def issResp = httpRequest(
                  url: issUrl,
                  acceptType: 'APPLICATION_JSON',
                  validResponseCodes: '200:404',
                  authentication: 'jenkins-api-creds'
                )
                if (issResp.status == 200) {
                  def issData = slurper.parseText(issResp.content)
                  def tools = issData.tools ?: []
                  for (tool in tools) {
                    if (tool.id == 'spotbugs' || tool.name?.toLowerCase()?.contains('spotbugs')) {
                      bugsTotal = "${tool.size ?: 0}"
                      bugsHigh = "${tool.sizeHigh ?: 0}"
                      bugsMedium = "${tool.sizeNormal ?: 0}"
                      bugsLow = "${tool.sizeLow ?: 0}"
                    }
                  }
                }
              } catch (e) {
                echo "Issues fetch failed for ${name}: ${e.message}"
              }
            }

            rows.add([
              name: name,
              color: color,
              build: buildNum ?: '-',
              coverage: coverage,
              bugsTotal: bugsTotal,
              bugsHigh: bugsHigh,
              bugsMedium: bugsMedium,
              bugsLow: bugsLow
            ])
          }

          // 3. Sort by name
          rows.sort { it.name }

          // 4. Generate HTML
          def html = """<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <title>Microservices Quality Dashboard</title>
  <style>
    body { font-family: system-ui, sans-serif; margin: 2rem; }
    h1 { color: #1a73e8; }
    table { border-collapse: collapse; width: 100%; }
    th, td { border: 1px solid #ddd; padding: 8px 12px; text-align: center; }
    th { background: #1a73e8; color: white; }
    tr:nth-child(even) { background: #f9f9f9; }
    .green { color: #27ae60; font-weight: bold; }
    .yellow { color: #f39c12; font-weight: bold; }
    .red { color: #e74c3c; font-weight: bold; }
    .na { color: #999; }
    .svc-name { text-align: left; font-weight: bold; }
    .timestamp { color: #888; font-size: 0.85em; margin-bottom: 1rem; }
  </style>
</head>
<body>
  <h1>Microservices Quality Dashboard</h1>
  <p class="timestamp">Generated: ${new Date()}</p>
  <table>
    <tr>
      <th>Service</th>
      <th>Build</th>
      <th>Status</th>
      <th>Coverage</th>
      <th>Bugs (Total)</th>
      <th>High</th>
      <th>Medium</th>
      <th>Low</th>
    </tr>"""

          for (row in rows) {
            def statusClass = row.color.contains('blue') ? 'green' :
                              row.color.contains('yellow') ? 'yellow' :
                              row.color.contains('red') ? 'red' : 'na'
            def statusText = row.color.contains('blue') ? 'PASS' :
                             row.color.contains('yellow') ? 'UNSTABLE' :
                             row.color.contains('red') ? 'FAIL' : row.color.toUpperCase()

            html += """
    <tr>
      <td class="svc-name">${row.name}</td>
      <td>#${row.build}</td>
      <td class="${statusClass}">${statusText}</td>
      <td>${row.coverage}</td>
      <td>${row.bugsTotal}</td>
      <td class="${row.bugsHigh != '0' && row.bugsHigh != 'N/A' ? 'red' : ''}">${row.bugsHigh}</td>
      <td class="${row.bugsMedium != '0' && row.bugsMedium != 'N/A' ? 'yellow' : ''}">${row.bugsMedium}</td>
      <td>${row.bugsLow}</td>
    </tr>"""
          }

          html += """
  </table>
</body>
</html>"""

          writeFile file: 'dashboard.html', text: html
        }
      }
    }
    stage('Publish Dashboard') {
      steps {
        publishHTML(target: [
          reportDir: '.',
          reportFiles: 'dashboard.html',
          reportName: 'Quality Dashboard',
          keepAll: true,
          alwaysLinkToLastBuild: true,
          allowMissing: false
        ])
      }
    }
  }
}

Important: Replace jenkins-api-creds with your Jenkins credential ID (see Step 5). Replace microservices-quality with your actual folder name if different.

Step 5: Create Jenkins API Credentials

The aggregator script calls the Jenkins REST API. It needs credentials to authenticate.

  1. Go to Manage Jenkins → Credentials → (global) → Add Credentials.
  2. Choose Username with password.
  3. Enter:
    • Username: your Jenkins username (or a dedicated API user).
    • Password: your Jenkins API token (generate from your user profile → Configure → API Token → Add new token).
    • ID: jenkins-api-creds (must match the script).
  4. Click Create.

Step 6: Approve Groovy Scripts (if required)

Jenkins sandboxing may block some Groovy methods. If the build fails with a script approval error:

  1. Go to Manage Jenkins → In-process Script Approval.
  2. Approve the pending method signatures (e.g. new groovy.json.JsonSlurper, httpRequest, etc.).
  3. Re-run the build.

Step 7: Run the Aggregator and View the Dashboard

  1. Open the quality-dashboard-generator job.
  2. Click Build Now.
  3. After a successful build, click Quality Dashboard in the left sidebar (added by HTML Publisher).
  4. You will see a single HTML page like this:
Service Build Status Coverage Bugs (Total) High Medium Low
cart-service#12PASS78%3120
inventory-service#8PASS85%2011
order-service#15UNSTABLE72%5221
payment-service#6PASS91%0000

(Example output — actual values come from your Jenkins jobs.)

Step 8: Auto-Refresh / Schedule

  • The aggregator runs on a cron schedule (e.g. every 30 min) so the dashboard is always up to date.
  • You can also trigger it after any microservice build completes (use "Build after other projects are built" in the trigger section).
  • The Quality Dashboard link on the aggregator job always shows the latest report.

These are the Jenkins API URLs the script calls for each microservice job:

MetricAPI URL

Tip: You can test these URLs in your browser (append ?pretty=true for readable JSON) to see what data is available and adjust the script accordingly.
