Step-by-Step Jenkins Integration

Code Quality (SpotBugs) and Code Coverage (JaCoCo) for Java Maven projects.

Part A: Jenkins Setup

Step 1: Install Required Plugins

  1. Open Jenkins in your browser.
  2. Go to Manage Jenkins → Plugins (or Manage Jenkins → System → Plugins).
  3. Open the Available tab.
  4. Search and install:
    • JaCoCo
    • Warnings Next Generation (Warnings NG / Static Analysis Utilities)
  5. If prompted, restart Jenkins (Manage Jenkins → Restart).
  6. After restart, go to Manage Jenkins → Plugins → Installed and confirm both plugins are listed.

Step 2: Global Tool Configuration (Java, Git, Maven)

Go to Manage Jenkins → Tools (or Global Tool Configuration).

JDK (Java)

  1. Under JDK, click Add JDK.
  2. Set Name to e.g. JDK-17.
  3. Either enable Install automatically and choose a Java 17 version, or set the path to an existing JDK 17 installation.

Git

  1. Under Git, click Add Git.
  2. Set Name to e.g. Default (or leave default).
  3. Either enable Install automatically or set the path to git on the agent.

Maven

  1. Under Maven, click Add Maven.
  2. Set Name to e.g. Maven-3.9.
  3. Either enable Install automatically and choose a version (e.g. 3.9.x), or set the path to an existing Maven installation.

Click Save.

Step 3: Create the Pipeline Job

  1. From the Jenkins dashboard, click New Item.
  2. Enter a name (e.g. codequality-demo).
  3. Select Pipeline.
  4. Click OK.

Step 4: Define the Pipeline

Option A – Pipeline script from SCM (recommended)

  1. In the job configuration, under Pipeline:
    • Definition: Pipeline script from SCM.
    • SCM: Git.
    • Repository URL: your repo URL (e.g. https://github.com/your-org/codequality-demo.git).
    • Credentials: add if the repo is private.
    • Branch: */main or */master.
    • Script Path: Jenkinsfile.
  2. Click Save.

Add a file named Jenkinsfile in the root of your repository with the content below (adjust the tool names if you used different ones).

Option B – Pipeline script (paste in Jenkins)

  1. Under Pipeline, set Definition to Pipeline script.
  2. Paste the same script into the Script text area.
  3. Ensure the job still has a way to get the source (e.g. a previous SCM step or “Pipeline script from SCM” for another branch).
  4. Click Save.

Jenkinsfile content

Use this version so the pipeline runs on both Linux/Unix and Windows agents (Windows does not have sh; it uses bat).

// Cross-platform: uses 'sh' on Linux/Unix agents and 'bat' on Windows agents
pipeline {
  agent any
  tools {
    jdk 'JDK-17'
    maven 'Maven-3.9'
  }
  options {
    buildDiscarder(logRotator(numToKeepStr: '30'))
    timestamps()
  }
  stages {
    stage('Build & Test') {
      steps {
        script {
          if (isUnix()) {
            sh 'mvn clean verify'
          } else {
            bat 'mvn clean verify'
          }
        }
      }
    }
    stage('Publish JaCoCo') {
      steps {
        jacoco(
          execPattern: 'target/jacoco.exec',
          skipCopyOfSrcFiles: true
        )
      }
    }
    stage('Publish SpotBugs') {
      steps {
        recordIssues(
          tools: [spotBugs(pattern: 'target/spotbugsXml.xml')]
        )
      }
    }
  }
  post {
    always {
      archiveArtifacts artifacts: 'target/site/jacoco/**/*,target/spotbugsXml.xml', allowEmptyArchive: true
    }
  }
}

Use the same tool names as in Global Tool Configuration (JDK-17, Maven-3.9). If you did not add a JDK, remove the jdk 'JDK-17' line.

Windows: If your Jenkins agent is Windows, the pipeline must use bat instead of sh for shell steps. The script above uses isUnix() so it works on both. If you only use Windows, you can replace the Build & Test step with bat 'mvn clean verify'.

Step 5: Run the Job and Verify

  1. Open the job and click Build Now.
  2. Wait for the build to finish. In the build’s Stages you should see:
    • Build & Test – runs mvn clean verify.
    • Publish JaCoCo – records coverage.
    • Publish SpotBugs – records static analysis.
  3. On the build page (click the build number):
    • You should see Coverage (or a coverage trend) from JaCoCo.
    • You should see Issues / Warnings from SpotBugs.
    • Under Build Artifacts, open the archived JaCoCo HTML (e.g. index.html under target/site/jacoco) for line-level drill-down.

Part D: Troubleshooting

  • “Maven” or “JDK” not found: The names in tools { ... } must match exactly the names in Manage Jenkins → Tools.
  • Cannot run program "sh" / The system cannot find the file specified (Windows): The agent is Windows; there is no sh. Use the cross-platform Jenkinsfile above (with isUnix() ? sh(...) : bat(...)), or replace sh 'mvn clean verify' with bat 'mvn clean verify' in the Build & Test stage.
  • No coverage / no issues: Ensure the Build & Test stage runs first and succeeds (mvn clean verify). Check that the paths above exist after the build.
  • Repo not found: Check repository URL, credentials, and branch. If using “Pipeline script” only, add a checkout scm or git step so the project is checked out.
  • SpotBugs HTML not archived: If the report is at target/spotbugs.html, add it to the archive list: target/site/jacoco/**/*,target/spotbugsXml.xml,target/spotbugs.html.

Note: This project uses Java 17, Maven, JaCoCo, and SpotBugs. The Jenkinsfile assumes tool names JDK-17 and Maven-3.9; change them to match your Jenkins configuration.
